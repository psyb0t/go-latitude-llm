# go-latitude-llm

Unofficial Go client for the Latitude LLM ops platform API at latitude.so, generated from Latitude's public OpenAPI document. For using the client from an agent, read [.agents/skills/go-latitude-llm/SKILL.md](.agents/skills/go-latitude-llm/SKILL.md). This file covers changing the repository.

## Architecture

One generated package, `latitude`, at the module root, driven by `gen.go`:

`scripts/fetch-spec.sh` downloads `https://raw.githubusercontent.com/latitude-dev/latitude-llm/main/apps/api/openapi.json` to `api/openapi.json`. `scripts/patch-spec.sh` writes `api/openapi.patched.json`, converting OpenAPI 3.1 nullable types, nullable enums and numeric exclusive bounds to 3.0 form. oapi-codegen reads that file with `config.yaml` and writes `client.gen.go`.

## Stack

- Go 1.26.10.
- oapi-codegen v2.8.0, pinned as a `tool` dependency in `go.mod`.
- Runtime: `github.com/oapi-codegen/runtime`.

## Layout

- `gen.go`, `config.yaml`, `client.gen.go`: the package.
- `client_test.go`, `example_test.go`: HTTP contract tests and the README example.
- `scripts/`: spec download, schema patches, lint and security scans.
- `api/`: downloaded and patched specs, gitignored.
- `vendor/`: dependency sources, regenerated by `make dep`.
- `.agents/`: project rules, the client skill and plugin manifests.

## Dev workflow

Everything runs in the `Dockerfile.dev` image. You need Docker and Make.

```bash
make dep       # go mod tidy + go mod vendor
make generate  # download the spec and regenerate
make lint      # shellcheck, shfmt, go fix, golangci-lint
make test      # go test -race
make sec       # gitleaks, govulncheck, semgrep
```

## Project-specific landmines

- This is Latitude LLM at latitude.so, not Latitude.sh.
- The source is OpenAPI 3.1.0. Nullable type arrays and numeric exclusive bounds require `scripts/patch-spec.sh` before the 3.0-oriented generator can read them. Null enum members are represented through `nullable: true`.
- Keep the `number` to `float64` mapping in `config.yaml`.
- API keys are organization-scoped HTTP Bearer credentials. The generated client does not add auth; use `WithRequestEditorFn`. The base URL is `https://api.latitude.so`; paths already include `/v1`.
- Creating saved searches and inviting, updating or removing members require user OAuth tokens according to the operation descriptions, despite their `ApiKeyAuth` security declarations. Token acquisition is outside the generated client.
- API-key account responses have null `user` and `role`. Nullable schemas become pointers; check before dereferencing.
- Method names come from operation IDs. Success can be `JSON200` or `JSON201`. HTTP errors are parsed responses, not Go errors; inspect the status and error body.
- The spec says project listing returns all projects in one page. Other collections expose cursors. Do not invent a cursor parameter on `ListProjects`.
- `make generate` downloads the current upstream spec. Review changes after every regeneration. Never edit `client.gen.go` by hand.
- Security scans always scan the worktree. The history scan runs only when Git metadata exists, so a source archive or new directory is usable without initializing Git.
- `.github/workflows/regen.yml` runs daily, checks regenerated code, and can tag releases when installed in a published repository. Its `fix_protected_paths` prevents automated repairs to workflows, Makefile, rules, scanner configs and the lint, security and download scripts. A failure needing those paths requires a manual fix.
